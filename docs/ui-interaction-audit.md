# Qt 前端交互审计

审计范围为当前 CMake 实际构建入口 `client_qt/src/main.cpp`。仓库中没有 HTML、CSS、
JavaScript 或独立 Web 服务，因此不存在可直接运行的“网页”；当前前端是 Qt Widgets
客户端。

## 已可运行

- 注册、登录、注销、刷新、目录进入与返回；
- 新建目录、上传文件/文件夹、下载文件/文件夹、重命名、删除；
- 单文件提取码创建和领取；
- 文件悬停预览：文本、图片、PDF 与视频预览请求；
- 搜索过滤、上传/下载进度更新、右键菜单操作。

## 已展示但当前不能完成业务

| 界面入口 | 当前状态 | 原因 | 建议处理 |
|---|---|---|---|
| 左侧“个人文档、共享文档、群组文档、文档库、归档库、收发任务、回收站、隔离区” | 无业务跳转 | 仅创建按钮，未连接信号 | 未实现前改为不可点击并标注“规划中”，或逐项补充后端协议与页面状态 |
| 左侧“权限共享、外链共享、发现共享、已屏蔽共享” | 无业务跳转 | 当前协议只有单文件提取码 | 先统一到“提取码分享”，权限/外链需新增 ACL 与链接 token 协议 |
| 左侧审核管理三项 | 无业务跳转 | 无申请、审批、工作流数据模型 | 暂时隐藏，后续按角色/审批表实现 |
| 工具栏“权限配置” | 明确禁用 | 源码设置 `setEnabled(false)` | 保持禁用并在 README 标明，待 ACL 完成再开放 |
| 活动日志 | 不可见 | `log->setVisible(false)`，没有开关 | 增加“活动记录”抽屉或调试开关 |
| DOCX/PDF 转 Markdown | 当前构建入口未提供菜单入口 | `FileBrowser` 当前信号中无转换操作 | 恢复右键“保存为 Markdown”并连接 `QtClient::convertToMarkdown` |

## 连接失败的易混淆点

`NO_CONNECTION: ClientCore not initialized` 不是登录失败。它表示创建 `QtClient` 时目标
`IP:端口` 无法连接。应先验证服务端地址；本机服务端使用 `127.0.0.1:9000`，局域网客户端
使用服务端电脑当前 IPv4 地址和端口 `9000`。

## 建议优先级

1. 将没有业务实现的侧栏入口禁用或隐藏，避免“看起来可点击但无响应”；
2. 恢复 Markdown 转换入口，补齐现有服务端已支持的功能；
3. 再实现权限、外链、审核等需要新数据模型和协议的功能，而不是只增加按钮。
