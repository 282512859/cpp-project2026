# 界面扩展功能说明（回收站 / 共享 / 权限 / 群组）

本文档说明这一版新增的界面功能、协议编号、数据表与验证方式。
它取代 `docs/ui-interaction-audit.md` 中“当前不能完成业务”的那张表：
那一版的侧栏入口现在都有真实业务，工具栏“权限配置”也已启用。

## 一、新增能力总览

| 界面入口 | 现在可以做什么 | 使用的扩展操作 |
|---|---|---|
| 个人文档 | 平铺列出我的全部文件（含所在目录、秒传指纹） | `library.list` |
| 共享文档 | 查看别人授权给我的文件，并领取到我的文档 | `share.list` / `share.claim` |
| 群组文档 | 建群、邀请成员、把文件加入群组、成员领取 | `group.*` |
| 文档库 | 原有文件树（上传、下载、重命名、删除、提取码等保持不变） | 核心协议 |
| 归档库 | 查看已归档内容、取消归档、移入回收站 | `archive.*` |
| 收发任务 | 我发出的提取码/外链、我用外链领取的记录 | `transfer.list` |
| 回收站 | 软删除、恢复到原目录、彻底删除、清空 | `trash.*` |
| 隔离区 | 扫描可执行文件并隔离、解除隔离、彻底删除 | `quarantine.*` |
| 权限共享 | 查看授权记录、新增授权、取消授权 | `permission.*` |
| 外链共享 | 创建带有效期/密码/可发现的外链、复制分享码、撤销 | `link.*` |
| 发现共享 | 浏览他人公开发布的外链、领取、屏蔽分享者 | `discover.list` / `link.open` / `block.*` |
| 已屏蔽共享 | 查看并解除屏蔽 | `block.*` |
| 权限申请 | 对他人公开的文件发起读写/只读申请 | `request.*` |
| 权限审核 | 文件所有者批准或驳回申请，批准即自动授权 | `review.*` |
| 流程申请 | 提交扩容、权限变更、数据恢复等流程申请 | `workflow.*` |
| 工具栏“权限配置” | 对选中文件查看/配置共享授权 | `permission.node` |
| 左侧“存储空间” | 显示真实已用量与配额 | `quota` |

## 二、协议设计（兼容性）

扩展消息统一占用 **700～799** 号段，与核心协议已使用的 1～613 完全不重叠：

- `MessageType` 的底层类型是 `uint16_t`，扩展编号可以与原有报文共用同一条 TCP 连接；
- 协议版本号不变，旧客户端解析原有响应不受影响；
- 只升级一端时，另一端会把未知编号当成 `BAD_REQUEST`，双方原有功能仍然可用，
  因此可以灰度升级、也可以单独回退。

定义位置：`common/include/cloud/common/ExtendedMessageType.h`。

注意：`token` 字段专用于登录会话，客户端会自动填充；外链码统一使用 `shareToken`，
两者混用会被服务端判定为未登录（客户端也会主动拦截这种参数）。

## 三、服务端实现

新增 `ExtendedFeatureService`（`server/include|src/ExtendedFeatureService.h/.cpp`）：

- 使用**独立 SQLite 连接**创建 `ext_*` 表，通过外键引用既有 `users` / `nodes`，
  原表结构不变，旧数据库可原地升级；
- 两个连接都设置了 `sqlite3_busy_timeout`，短事务之间等待锁而不是直接报错；
- 回收站与隔离区用**隐藏父目录**实现：`-1` 回收站、`-2` 隔离区。节点被移出正常
  目录树后，普通列表/上传/下载都感知不到；恢复时写回原父目录，原目录若已删除则
  自动退回根目录；
- 彻底删除时调用 `CloudRepository::deleteNode`，复用已有的 blob 引用计数与配额回收，
  避免出现两套容易出错的回收逻辑；
- 跨用户“领取”（权限共享 / 外链 / 群组条目）统一走 `copyNodeForUser`：只增加 blob
  引用计数，物理文件不复制，等价于一次秒传，并按逻辑大小累加配额。

### 数据表

`ext_trash`、`ext_archive`、`ext_quarantine`、`ext_acl`、`ext_acl_requests`、
`ext_workflows`、`ext_share_links`、`ext_link_claims`、`ext_blocks`、`ext_groups`、
`ext_group_members`、`ext_group_items`。

### 与 ServerApp 的接入点

`ServerApp::handle()` 在解析完 JSON 正文后增加了一处分发：

```cpp
if (auto extended = extendedFeatures_.handle(request, body))
    return *extended;
```

返回空值表示“不是扩展请求”，继续走原有 `switch` 分支。

## 四、客户端实现

- `client_core`：`ExtendedClientCore` 使用**独立 TCP 连接与独立 token**，
  因此扩展请求不会插队打断正在传输的大文件；连接按需建立并复用，异常自动重连。
  调用方式是按操作名分发：`dispatch("trash.list")`、`dispatch("link.open", {...})`。
- `client_qt`：`FeatureHub` + `FeatureWorker`。Worker 运行在独立 `QThread` 中，
  所有网络调用都在那里阻塞，界面线程不会被拖住；界面沿用原有 `FileBrowser`、
  侧栏按钮与工具栏，只切换数据与可用动作。

### 主界面接入点（`client_qt/src/main.cpp`）

1. 引入 `client_qt/FeatureHub.h`；
2. 侧栏按钮按顺序登记视图标识（外观不变）；
3. 新增扩展视图工具栏，与原有文件工具栏互斥显示；
4. 工具栏“权限配置”由禁用改为可用，转交 `FeatureHub::openPermissionDialog()`；
5. 登录成功时 `FeatureHub::setSession(...)`，注销时 `clearSession()`；
6. 文件浏览器原有动作在扩展管理视图里加了一道护栏，避免把外链 ID、申请 ID
   误当成节点 ID 去下载或删除。

删除语义：文档库中的“删除”仍是原有行为，“移入回收站”在个人文档/文档库/归档库的
工具栏中单独提供，回收站里的“彻底删除”才真正释放磁盘。

## 五、验证方式

`tests/extended/ExtendedFeatureTests.cpp` 是端到端测试，覆盖 39 项断言：

```bat
cloud_server.exe 9200 <临时运行目录>
set LANCLOUD_EXTENDED_TEST_PORT=9200
cloud_extended_tests.exe 9200
```

实测结果（Windows / MSVC 19.44 / CMake Release）：

```text
检查 39 项，失败 0 项
```

注意：密码使用 PBKDF2-HMAC-SHA-256 迭代 60 万次。**Debug 未优化构建**下单次注册
可能超过 15 秒，客户端会先超时；做联调或验收时请使用 Release 构建。
